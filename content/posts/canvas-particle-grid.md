首页背景那层粒子会互相连线。最早的写法很直接——每颗粒子和其余所有粒子比一次距离：

```js
for (let i = 0; i < ps.length; i++) {
  for (let j = i + 1; j < ps.length; j++) {
    const dx = ps[i].x - ps[j].x;
    const dy = ps[i].y - ps[j].y;
    if (dx * dx + dy * dy < MAXD2) link(ps[i], ps[j]);
  }
}
```

320 颗就是 48828 次距离计算，每帧一次。线是画对了，但机器在白白发热。

## 网格分桶

连线的本质是"谁离谁近"。把屏幕切成边长等于连线半径的格子，每颗粒子只跟**同格 + 邻格**比：

```js
const cell = MAXD;                    // 格子边长 = 连线半径
const gx = Math.floor(p.x / cell);
const gy = Math.floor(p.y / cell);
const key = gx + ',' + gy;
```

为什么不会漏？因为"可能连上"的两颗粒子，距离一定小于 `MAXD`，
它们的格坐标最多差 1 —— 所以扫 3×3 邻域就够，一对都不会漏。

同一份粒子数据、同一个半径，两种写法的连线结果完全一致，距离计算从 48828 次降到 3186 次。

## 顺带省掉的两笔

| 事项 | 之前 | 现在 |
|---|---|---|
| 小圆点绘制 | 一颗一次 `fill()`，约 297 次/帧 | 按「颜色 × 透明度档」攒成十几条路径，11 次/帧 |
| 柔和光斑 | 每帧新建渐变对象，12 个/帧 | 1 张预渲染的 96×96 贴图，缩放贴上 |
| 指针写样式 | 每帧 2 次，不管变没变 | 变了才写，且降到 30Hz |
| 连线数组 | 每帧新建 4 个数组 | 复用，不产生垃圾 |

> 这些数字都是量出来的，不是估的：连线那两行把两套算法喂同样的粒子数跑过，
> 绘制调用数是用 `CanvasRenderingContext2D.prototype` 上的计数器在真实页面里数出来的。
> **没量的是帧时间**——无头软渲染环境里的噪声比差别还大，「到底还卡不卡」只能在自己机器上感受。

## 什么时候不用管

粒子少于 100 颗、或者页面本来就是静态的，别做这套优化：多出来的代码比省下来的那点时间贵。
