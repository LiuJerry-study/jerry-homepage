# 个人网站后台核心内容优化设计

日期：2026-10-14
状态：已确认，等待实现计划
方案：B：核心内容优先

## 1. 背景与目标

当前网站已经具备 Markdown 写作后台、实时预览、草稿预览、站点设置和首页卡片配置。后台能力分散在不同页面和配置入口，日常操作仍需要理解文件结构，缺少统一的工作台、内容状态和操作反馈。

本阶段目标是优化后台最常用的四条工作流：查看站点状态、管理内容、写作与预览、调整首页入口。改造必须保持现有零依赖、零外部请求、静态产物可双击打开、公开站点渲染方式不变。

## 2. 范围

### 2.1 第一阶段包含

1. 总览仪表盘
2. 内容管理
3. 紧凑型文章编辑器
4. 首页卡片管理

### 2.2 第一阶段保留现有入口

素材库、发布中心和系统状态在第一阶段保留现有基础能力与入口，完整增强放入后续阶段。

### 2.3 后续阶段

第二阶段增加发布中心、构建记录、版本快照、一键回滚、素材库和站点健康检查。

第三阶段增加快捷键、最近编辑、收藏、模板、草稿提醒、内容统计和中文搜索增强。

第四阶段增加多管理员、权限分级、登录日志、操作日志、会话管理和更细的备份恢复策略。

## 3. 统一界面结构

后台使用统一工作台结构：

- 左侧固定导航：总览、内容管理、首页卡片、素材库、站点设置、发布中心。
- 顶部显示当前页面路径、标题、保存状态和主要操作。
- 主区域统一使用卡片、表格和双栏编辑布局。
- 主要操作固定在右上角，例如新建文章、保存并发布、预览网站。
- 统一绿色视觉、间距、圆角、按钮、表格和状态标签。

状态反馈分为四类：

- 绿色：已保存、已发布、检查通过、运行正常。
- 黄色：草稿、待完善、缺少封面、缺少替代文本。
- 红色：保存失败、构建失败、配置错误。
- 灰色：隐藏、未使用、尚未发布。

## 4. 页面设计

### 4.1 总览仪表盘

展示已发布内容数量、草稿数量、首页入口数量和最近构建状态。提供最近编辑内容列表、发布健康度、快速新建和公开网站预览入口。

最近内容至少显示标题、类型、更新时间和状态。发布健康度显示页面链接、草稿、图片和构建相关检查结果。

### 4.2 内容管理

提供全部内容、文章、作品、草稿和回收站视图。列表支持标题、标签、正文搜索，支持状态筛选和更新时间排序。

每行显示选择框、标题、摘要信息、类型、更新时间、状态和更多操作。单条操作包括编辑、预览、复制、移入回收站和恢复。批量操作第一阶段支持归档、移入回收站、恢复以及修改分类或标签。

### 4.3 紧凑型文章编辑器

编辑器以 Markdown 编辑区为主，右侧显示固定宽度的实时预览。预览区域独立滚动，页面整体高度保持紧凑，不把预览内容堆叠到编辑区下方。

编辑器顶部显示内容路径、标题、自动保存状态、整页预览和发布更新按钮。底部或侧边显示发布状态、搜索摘要、标签和封面提醒。

窄屏设备默认收起预览，用户通过预览按钮按需打开。正式页面预览继续使用现有同源渲染器，保证后台预览与正式页面结构一致。

### 4.4 首页卡片管理

提供首页入口列表，支持拖动排序、标题编辑、描述编辑、图标编辑、链接编辑和显示 / 隐藏开关。右侧提供桌面端首页即时预览。

保留随机主题、随机转场和添加入口等首页行为开关。用户点击保存并发布后，写回首页卡片配置并触发站点重新渲染。

## 5. 数据与保存流程

第一阶段沿用现有文件型内容架构：

- 文章：`content/posts/*.md`
- 作品：`content/projects/*.md`
- 首页设置：`content/settings.json`
- 首页卡片：`content/nav.json`
- 简历、关于页和其他 JSON 内容保持兼容

统一流程：

```text
读取文件 → 解析 Markdown / JSON → 转换成列表和表单 → 用户编辑
→ 内容校验 → 写回原文件 → 触发站点重新渲染 → 返回结果
```

保存时检查标题、文件名、日期、标签、图片路径、文章链接、草稿状态和页面开关状态。保存成功后返回最新保存时间，保存失败时保留编辑器内容并显示具体原因。

`draft: true` 的内容只保留在后台，`draft: false` 的内容保存后进入公开站点。首页卡片保存后即时更新公开首页。

## 6. 错误处理与边界

- 文件不存在时显示明确的内容缺失状态，不显示空白页面。
- Markdown 或 JSON 解析失败时保留原文件，不覆盖损坏内容。
- 图片路径失效时显示对应文件名和修复提示。
- 批量操作前显示选中数量和操作范围。
- 删除操作先进入回收站，避免直接丢失内容。
- 所有保存和发布操作显示进行中、成功或失败状态。
- 现有“所有页面全部关闭时拒绝保存”的安全阀继续保留。
- 不引入数据库，不改变公开站点服务和静态构建产物之间的现有关系。

## 7. 验证标准

实现后必须验证：

- 后台首页和登录流程正常。
- 文章、作品、草稿列表与文件内容一致。
- 新建、编辑、保存、预览和发布流程完整可用。
- Markdown 实时预览与正式页面结构一致。
- 首页卡片排序、编辑、隐藏和保存有效。
- 搜索、筛选、分页和批量操作有效。
- `draft: true` 的内容不会出现在公开页面。
- 保存失败时不会丢失当前编辑内容。
- 桌面端和窄屏布局正常。
- 现有 `npm run check`、`npm run verify` 等检查继续通过。
- 零外部请求、零运行时依赖和静态站点可双击打开的原则保持不变。

第一阶段成功标准：用户可以在统一后台完成查看状态、管理内容、写文章和调整首页，不需要频繁打开文件夹或直接编辑 JSON。

## 8. 实施边界

本设计只定义第一阶段后台体验和必要的内容管理能力，不包含第三方统计、评论、外部字体、数据库迁移、服务器架构替换和公开站点视觉重做。
