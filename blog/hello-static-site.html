为什么要动结构

原来的 personal-site 是四个文件：index.html、assets/styles.css、assets/main.js、assets/site-data.js。 好处是双击就能看，坏处也在这：main.js 有 2170 行、styles.css 有 1532 行， 想改某一处得先滚到对应的位置；而「博客」「作品集」这些卡片点开永远是占位详情页——因为没有真页面。

这次只做一件事：把骨架换掉，把外观留下。

  • 源文件拆成 src/styles/*.css（20 个章节）和 src/js/*.js（13 个章节），改哪一块就看哪个文件；
  • 加一个 scripts/build.mjs，把源文件拼回 assets/styles.css 和 assets/main.js；
  • 内容搬进 content/：文章是 Markdown，项目是 Markdown，简历是 JSON；
  • 构建时顺便生成 blog/、projects/、resume.html，以及 sitemap.xml、rss.xml、robots.txt。

为什么不用打包器

因为这个站点的身份是"零依赖、双击就能看"。

一旦引入 webpack / vite，就多出一条 npm install 的命令， 而这些页面的交互其实只有粒子、转场、命令面板那几件事——不值得为此背上一个工具链。

所以构建脚本只用 Node 内置模块：拼接、渲染 Markdown、写文件，没了。 代价是 Markdown 渲染器得自己写一份（scripts/lib/markdown.mjs）， 好处是服务器上只要装了 Node，node scripts/build.mjs 就能出站， 不需要 node_modules，不需要锁文件，也不会因为某个包三年不更新而构建失败。

顺便记一个坑：面板里的紧凑系数 --k 只在舞台上存在。 长页面如果没定义 --k，所有 calc(28px * var(--k)) 的声明会整条失效—— 不是变成 0，而是整条被丢掉。所以长页面必须显式写 --k: 1。
