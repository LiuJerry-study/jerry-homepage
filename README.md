# 个人门户 · personal-site

一个**导航门户**：**第一屏就是导航本身** —— 一句主标语「未来 由我们创造」压在上面，
下面整墙铺开简历 / 博客 / 作品集 / 笔记库这些入口。点卡片不弹小浮层，而是
**从右侧滑进一整屏详情页**。

风格：简约 · 高级 · 清新绿。两套主题，一屏一页。

**零运行时依赖**：没有 CDN、没有外部字体、没有 npm、没有 node_modules。
产物就是几个普通文件，**双击 `index.html` 就能看**，离线也能看。

> **版式定死了：一屏一页（逐屏），而且页面本身锁死不滚。** 翻屏不是把页面滚上去，
> 而是把整块面板在原地换掉；详情页是另一层、从右侧滑进来的整页。
> 博客 / 作品 / 简历是长页面，走另一套骨架（见「两套布局」）。

---

## 三种用法

| 你想做什么 | 怎么做 |
|---|---|
| **只想看** | 双击 `index.html`。没有构建、没有依赖，直接就能跑 |
| **改内容 / 写文章** | 改 `content/` 里的文件，然后 `node scripts/build.mjs` |
| **发布上线** | 看 [DEPLOY.md](DEPLOY.md)，一条 `bash scripts/deploy.sh` |

## 内容怎么写

### 1. 站点配置 `content/site.js`

首页唯一需要改的文件。加一张卡片 = 往 `nav` 里加一个对象：

```js
{
  title: '个人简历',
  desc: '教育经历 · 技能栈 · 项目经验',
  icon: 'resume',                 // 图标见 main.js 顶部 ICONS
  href: 'resume.html',            // 留空 = 显示「筹备中」，点开是详情页
  badge: '{{resume}}',            // {{posts}} / {{projects}} / {{resume}} 由构建换成真实数量
  tags: ['简历', 'resume', '教育'],  // 命令面板搜得到
  details: ['教育经历：学校 / 专业 / 时间线', '技能栈：按熟练度分层列出']
}
```

`href` 填上之后卡片自动变成真链接（站内写 `blog/index.html`，外链写完整 `https://`，
邮箱写 `mailto:…`）。**写 `blog/index.html` 而不是 `blog/`** —— 后者在 `file://` 下
会打开目录列表而不是页面。

### 2. 写一篇文章 `content/posts/我的文章.md`

文件名就是网址：`content/posts/hello.md` → `/blog/hello.html`。
建议文件名用英文或拼音，标题用中文（中文文件名能跑，但 URL 会被百分号编码）。

```markdown
---
title: 文章标题
date: 2026-10-10
tags: [前端, 笔记]
excerpt: 列表页和分享卡片上显示的一句话。不写就从正文自动提取。
draft: false
---

正文用 Markdown 写。
```

支持：标题（带锚点）、粗体、斜体、删除线、行内代码、链接、图片、裸网址、
有序/无序/嵌套列表、引用、围栏代码块（带高亮）、GFM 表格、分隔线。
正文里的 HTML 会被转义，不会原样输出。

`draft: true` 的文章不会被生成、也不会进列表和 RSS。

### 3. 加一个作品 `content/projects/项目名.md`

```markdown
---
title: 项目名
description: 一句话说明（列表卡片用）
date: 2026-09-30
tech: [Node.js, Markdown]
demo: https://demo.example.com
repo: https://github.com/you/repo
featured: true      # 列表里打一个 Featured 标记
order: 1            # 数字越小越靠前
excerpt: 详情页不会用，但 RSS / 分享卡片会用
---
```

### 4. 简历 `content/resume.json`

`intro` 是一段自我介绍，`sections` 支持两种类型：

```json
{
  "sections": [
    { "type": "skill",    "title": "技能栈", "en": "Skills",
      "items": [{ "name": "TypeScript", "level": "熟练" }] },
    { "type": "timeline", "title": "经历", "en": "Experience",
      "items": [{ "role": "前端工程师", "company": "某公司", "period": "2024 — 至今", "description": "做了什么" }] }
  ]
}
```

教育背景也用 `timeline`，多写 `major` / `degree` 两个字段即可。

## 命令

```bash
node scripts/build.mjs            # 完整构建
node scripts/build.mjs --assets   # 只重拼 CSS/JS/配置（改样式时最快）
node scripts/check.mjs            # 上线前自检（死链、占位符、必需产物）
node scripts/serve.mjs            # 本地预览 http://127.0.0.1:8000
bash scripts/deploy.sh            # 构建 → 自检 → 同步到服务器
```

有 `package.json` 但**没有任何依赖**，只是为了写起来短一点：

```bash
npm run build / assets / check / serve / deploy
```

### 为什么构建是"拼接"而不是打包器

站点要能在 `file://` 下双击打开，所以不能用 ES module、不能有外部依赖。
源文件拆开只为好读好改；构建脚本只做四件事：拼接、渲染 Markdown、写页面、写 SEO 产物，
全部只用 Node 内置模块。**服务器上只要有 Node，`node scripts/build.mjs` 就能出站**，
不需要 `npm install`，也没有依赖升级把构建搞坏的风险。

## 两套布局

| | 门户首页 | 博客 / 作品 / 简历 |
|---|---|---|
| `<html>` 标记 | `data-layout="stage"` | `data-layout="page"` |
| 文档滚动 | **锁死不滚**（`overflow: hidden`） | 正常长页面滚动 |
| 骨架 | 舞台 + 面板 + 详情层 | 顶栏 + 正文 + 页脚 |
| 脚本 | `assets/main.js`（粒子 / 转场 / 命令面板） | `assets/pages.js`（只有主题和年份） |
| 样式 | 同一份 `assets/styles.css` | 同一份 `assets/styles.css` |

两者共用同一套设计令牌和同一份样式表，所以点进博客页不会有"换了个网站"的感觉。
主题也共用 `localStorage` 的 `portal-theme`，在门户切了暗色，翻到博客页还是暗色。

> 一个容易踩的坑：面板的紧凑系数 `--k` 只在舞台里定义。
> 长页面没定义 `--k` 时，`calc(28px * var(--k))` 这种声明会**整条失效**
> （不是变成 0），所以长页面必须显式写 `--k: 1`。

## 首页交互一览

| 你做什么 | 它怎么回应 |
|---|---|
| 滚轮 / 空格 / `↓` | 翻到下一屏（**页面不动**，内容在原地换） |
| `↑` / `PgUp` | 上一屏 |
| `1` `2` | 直接跳到第 N 屏 |
| 右侧圆点 / 左下角屏序 | 点圆点跳屏；屏序旁边会写着这一屏用了哪套转场 |
| 拖动空白处 | 屏幕跟手挪一点点，松手看距离和速度：够就翻屏，不够就弹回去（有惯性） |
| 点一下大标题 | 整行字**散成粒子、撒满整个屏幕**，约两秒后逐字聚回来；散着的时候再点没反应 |
| 点任意空白 | **爆点**：把周围的粒子轰开，同时炸一下 |
| `Ctrl` / `⌘` + `K` | **命令面板**：搜页面、搜卡片（连 `tags` 一起搜）、执行动作 |
| `?` | 全部快捷键与互动一览 |
| `T` | 明 / 暗主题（从按钮位置圆形揭开） |
| 悬停卡片 | 停 0.42 秒出预览：这条目的前两条详情 |
| 点卡片 | 填过 `href` 的直接跳走；没填的**从右侧滑进整屏详情页** |
| 详情页开着时 | 滚轮、方向键、数字键都不会去翻底下的屏 |

### 三样东西是随机的

| 随机的 | 开关（都在 `content/site.js`） | 网址钉死 |
|---|---|---|
| **翻屏转场**：六套（淡入 / 推移 / 翻卡 / 缩放 / 虚化 / 擦除），不连着重复 | `randomTransition` | — |
| **点击爆点**：两套，每次点击**独立**掷一次 | `randomBurst` | `?fx=random` / `?fx=new` / `?fx=classic` |
| **主题**：首次打开随机亮 / 暗，手动切过一次就记住 | `randomTheme` | `?theme=light` / `?theme=dark` |

两套爆点长什么样、想看左右对照，开 **`proto/burst-lab.html`**。

> `content/site.js` 在 `<head>` 里加载，排在主题内联脚本前面 ——
> 主题要在首次绘制前定下来，那个脚本得先读得到开关。**改脚本顺序前先想一下这件事。**

## "页面不滚"是怎么做到的

一句话：**文档（`html` / `body`）被锁死成 `height:100%; overflow:hidden`，
翻屏从头到尾没碰过 `window.scrollTo`。**

```
body
├─ div.bg                     固定铺满视口：色洗 + 粒子 + 光斑 + 颗粒
├─ main.stage                 固定铺满视口，overflow:hidden
│  ├─ section.panel#home      ← 两块面板叠在同一格里
│  └─ section.panel#about        只有一块 .is-active（可见 + 可交互）
└─ section.item-page          详情页：默认为 translateX(100%)，加 .is-in 滑到位
```

翻屏 = 给走的那块加 `.is-out`、来的那块加 `.is-in` + 一个转场类，动画结束把类摘掉。
方向写在 `.stage[data-dir]` 上，CSS 里的 `--push / --rot / --ct / --cb` 随方向变，
所以六套动效都只写一遍。

**某一屏真的装不下怎么办？** 三步，不推翻版式：

1. **先收紧**：每块面板有紧凑系数 `--k`（1 → 0.64，每次减 0.06），JS 一档一档调，
   字号、间距、卡片高度跟着缩；
2. **再屏内滚**：`--k` 到底还排不下（手机上的卡片墙就是这种），就只让**那一屏内部**滚，
   文档仍然一动不动，左下角屏序旁会挂一个「↕ 屏内可滚」；
3. **到边界才翻屏**：屏内滚到底之后，再滚一下才翻到下一屏。

## 几个刻意的设计选择

- **不加载任何外部字体**：用系统字体栈（Segoe UI / 微软雅黑 / PingFang）。
  代价是各平台字形略有差异，换来的是**首屏零网络请求**、离线可用、不会被墙。
- **绿色只用在几个地方**：光晕、主按钮、标题里「未来」两字、卡片聚光、屏序。
  其余全是低饱和的墨绿灰阶 —— 「清新」靠留白和色相，「高级」靠克制。
  长页面的代码高亮也守这条：只有深浅和字重差异，不加彩虹色。
- **颗粒质感**：背景叠了一层 3.5% 的噪点（纯 CSS 内联 SVG），防止大面积渐变色带。
- **能点的字不许选中**：整站 `user-select: none`。真正要复制的地方只留两处：
  命令面板的输入框、详情页 / 长页面的正文。
- **大字只动一下**：首屏标题不拖、不位移，唯一的互动是「点一下散成粒子」。
- **详情页是整屏滑入**，不是卡片上弹小面板：不用算坐标、不用铺遮罩，
  也不打断「一屏一页」的节奏；底下舞台的滚动位置和第几屏全都原样保留。
- **转场宁短不长**：最长 720ms，翻屏锁在转场期间，避免连点滚轮把状态搞乱。

### 性能账（每一条都有实测）

| 事项 | 之前 | 现在 |
|---|---|---|
| **连线**：每帧要算多少对粒子（320 颗） | 48828 次距离计算 | **3186 次（15×）**，连出来的线一模一样多 |
| **小圆点**：散开时每帧的画布 `fill()` | ~297 次 | **11 次（27×）** |
| **柔和光斑**：每帧新建的渐变对象 | 12 个/帧 | 1 张预渲染贴图，缩放贴上 |
| **指针位置写样式** | 每帧 2 次 | 变了才写，且降到 30Hz |
| **颗粒层混合面积** | 4 倍视口 | 1 倍视口 |
| **点击涟漪** | 每次点击新建一个最大 2600×2600px 的 DOM 层 | 画布上的几个圆、几条线 |

做法就三条：**别做平方级的事**（粒子按连线半径装进网格，只比同格 + 邻格）、
**绘制调用要合并**（按颜色 × 透明度档攒路径，一次 `fill`）、
**别每帧做无用功**（值没变就不写样式、不新建渐变对象）。

> 哪些是量出来的、哪些是推理出来的：表里的数字都是量出来的；
> **没量的是帧时间** —— 无头软渲染环境里的噪声比差别还大，
> 「到底还卡不卡」只能在自己的机器上感受。`proto/burst-lab.html` 就是为这个准备的。

## 兼容与已知边界

| 事项 | 说明 |
|---|---|
| 浏览器 | 现代 Chromium / Safari 15.4+ / Firefox 121+。用到了 `translate` 属性、`clip-path` 转场等 |
| `file://` 直接打开 | 可以。全部是传统 `<script>`，没用 ES module（module 在 `file://` 下会被 CORS 拦）。站内链接写 `blog/index.html` 而不是 `blog/`，就是为了这个 |
| **改了文件、页面却没变** | 静态资源会被浏览器缓存。先 `Ctrl+F5`。线上不会：HTML 是 `no-cache`，CSS/JS 带 `?v=` 版本串 |
| 禁用 JavaScript | 首页退回普通长页面，两屏竖着排、内容都在（`<noscript>` 里那段样式），只是没有转场、详情页和互动 |
| `prefers-reduced-motion` | 全部动效退化为直出（详情页直接出现/消失），导航照常 |
| 触屏 / 触控笔 | `(pointer: coarse)` 时关掉 3D 倾斜、旧爆点的 DOM 圆，新爆点的火星减量 |
| 窗口偏矮 / 面板装不下 | 先按 `--k` 收紧；紧到底才允许那一屏内部滚动，并挂出「↕ 屏内可滚」 |
| 手机 | 首屏单列卡片 + 屏内滚动，翻屏用圆点；详情页整屏可滚，向右滑返回 |
| Markdown | 自写的渲染器，不做 CommonMark 全兼容；正文 HTML 一律转义 |
| 构建 | 需要 Node 18+。**服务器上不需要** —— 构建在本地做，只上传产物 |

## 部署

站点是纯静态的：服务器上不需要 Node、数据库或常驻进程，一个 nginx 就够。

**完整步骤见 [DEPLOY.md](DEPLOY.md)**，包括：改域名 → 构建 → 上传 → nginx 配置 →
HTTPS → 日常发布流程 → 回滚 / 备份 → 常见问题。
仓库里备好了 `deploy/nginx.conf`（含缓存策略、gzip、404、安全头）和
`scripts/deploy.sh`（构建 + 自检 + rsync 一条命令）。
